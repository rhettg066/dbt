## dbt-core 1.14.0-a1 - November 11, 2026

### Breaking Changes

- Flags introduced in 1.9 and 1.10 defaults to true ([#12713](https://github.com/dbt-labs/dbt-core/issues/12713))
- Drop support for Python 3.10, which has reached end-of-life ([#TBD](https://github.com/dbt-labs/dbt-core/issues/TBD))

### Features

- Add OpenTelemetry span instrumentation for node and hook execution, gated behind the --snowflake-projects-otel flag (off by default) ([#11367](https://github.com/dbt-labs/dbt-core/issues/11367))
- Add hints for cli users based on dbt usage ([#15510](https://github.com/dbt-labs/dbt-core/issues/15510))
- Warn users if they are using a deprecated dbt version ([#15964](https://github.com/dbt-labs/dbt-core/issues/15964))
- Extend RunResult with the state_decision_id attribute ([#0](https://github.com/dbt-labs/dbt-core/issues/0))
- Add otel_trace_id() and otel_span_id() Jinja functions to correlate query comments and model SQL with OpenTelemetry trace/span ids ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Announce dbt v2 availability as an INFO message on `dbt --version`, with a link to the v2 install docs ([#](https://github.com/dbt-labs/dbt-core/issues/))

### Fixes

- Recognize Databricks adapter config keys (`query_tags`, `zorder`, `options`, `unique_tmp_table_suffix`, `skip_optimize`) in jsonschema validation so they no longer raise spurious `CustomKeyInConfigDeprecation` warnings (dbt-databricks#1540, dbt-databricks#1302) ([#N/A](https://github.com/dbt-labs/dbt-core/issues/N/A))
- Fix partial parsing ghost-duplicate that raised a false "found two data_tests" error by cleaning up disabled generic and singular test nodes on schema re-parse ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Carry ref/source/function dependencies declared inside an overloaded UDF's overload body onto the root function node, so they are not dropped from the DAG when the overload SQL file is absorbed ([#15501](https://github.com/dbt-labs/dbt-core/issues/15501))
- Update reuse relations hint text ([#15510](https://github.com/dbt-labs/dbt-core/issues/15510))
- Fix macro namespace resolution so a dbt project named after a macro no longer crashes with 'MacroGenerator' during dispatch ([#15556](https://github.com/dbt-labs/dbt-core/issues/15556))
- Persist hint_ts in dbt_home and gate rw on bare Except clause to be more defensive ([#15510](https://github.com/dbt-labs/dbt-core/issues/15510))
- Fix `dbt build` node count ("X of Y") being inflated when unit tests are selected, by adding the unit test count to num_nodes exactly once instead of on every dequeue while run_count is still 0 ([#11185](https://github.com/dbt-labs/dbt-core/issues/11185))
- Stop resolving a unit test's tested model eagerly at parse time; resolve it only in the single deterministic post-parse pass so resolution no longer depends on filesystem parse order at all (deeper fix for ([#11139](https://github.com/dbt-labs/dbt-core/issues/11139))
- Fall back to per-source freshness checks when batch metadata freshness computation fails, instead of skipping every selected source now that `skip_nodes_if_on_run_start_fails` defaults to True ([#15634](https://github.com/dbt-labs/dbt-core/issues/15634))
- Re-parse adapter macros from the installed adapter package after loading a Fusion-generated manifest, ensuring the user's installed dbt-<adapter> version is used instead of Fusion's compile-time bundled copy ([#15527](https://github.com/dbt-labs/dbt-core/issues/15527))
- Fix OpenTelemetry hook spans: name them by hook and transaction phase, skip calls that run no hooks, and add node context and status. ([#11367](https://github.com/dbt-labs/dbt-core/issues/11367))
- Scope relation-cache population in `compile`/`show`/`docs generate` to the selected nodes' schemas so `--cache-selected-only` is honored (previously only `run` respected the flag) ([#12944](https://github.com/dbt-labs/dbt-core/issues/12944))
- Re-parse the built-in generic tests (test_not_null, test_unique, test_accepted_values, test_relationships) after loading a Fusion-generated manifest, so they are not permanently evicted and left undefined at test-compile time ([#15914](https://github.com/dbt-labs/dbt-core/issues/15914))
- Write target/manifest.json from the corrected in-memory manifest after loading a Fusion-generated manifest, so the on-disk artifact reflects the rediscovered adapter macros actually used for compilation instead of Fusion's raw bundled macros ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Send the `x-ms-blob-type: BlockBlob` header and accept `201 Created` when uploading artifacts to an Azure Blob Storage signed URL, so artifact ingestion no longer fails with `400 MissingRequiredHeader` on Azure-hosted regions. Upload errors now include the storage provider's error code alongside the status code. ([#N/A](https://github.com/dbt-labs/dbt-core/issues/N/A))
- Capture and re-emit fusion parser subprocess output through dbt-core's event system instead of letting it pass through to raw stdout/stderr, re-leveling each line by its json-compat severity when available ([#15672](https://github.com/dbt-labs/dbt-core/issues/15672))
- Validate that a resolved package installation path stays within the configured packages-install-path ([#N/A](https://github.com/dbt-labs/dbt-core/issues/N/A))
- Fix `statically_parse_unrendered_config` stringifying list/dict config values, which caused false positives in `state:modified` comparisons across different dbt versions. ([#16133](https://github.com/dbt-labs/dbt-core/issues/16133))
- Relay the v2 (Fusion) parser's log output via --log-format otel instead of json-compat, dropping span noise, keeping fusion's error/warning codes, and fixing a latent bug where a stray fusion stderr line could abort the run under --warn-error ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Reword the snapshot timestamp data type mismatch warning to identify hard-delete timestamps as the affected columns and to recommend overriding the `snapshot_get_time` macro, instead of incorrectly suggesting a change to the snapshot's `updated_at` config ([#fs-14450](https://github.com/dbt-labs/dbt-core/issues/fs-14450))
- Fix `Dimension` to satisfy the `metricflow-semantic-interfaces` protocol and bump the `metricflow` floor to 0.213.0 ([#](https://github.com/dbt-labs/dbt-core/issues/), [#](https://github.com/dbt-labs/dbt-core/issues/))
- Bare wildcard FQN selectors (e.g. `-s "f_*"`) now match nested models regardless of subfolder depth ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Fix cumulative metrics with an `input_metric` and a top-level `window` field (v2 metric spec) incorrectly failing to parse with a legacy nested-`type_params` error ([#N/A](https://github.com/dbt-labs/dbt-core/issues/N/A))
- Fix compiled_code not persisted to manifest.json when using --use-v2-parser ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Include `semantic_manifest.json` in the artifact set uploaded by `--upload-to-artifacts-ingest-api`, matching other run artifacts ([#N/A](https://github.com/dbt-labs/dbt-core/issues/N/A))
- Log invalid dbt_project.yml flags using existing project error events ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Validate that tarball package download locations stay within the dbt downloads directory ([#](https://github.com/dbt-labs/dbt-core/issues/))
- Recognize Databricks Python model config keys (`access_control_list`, `notebook_access_control_list`) in jsonschema validation so they no longer raise spurious `CustomKeyInConfigDeprecation` warnings (dbt-databricks#1661) ([#N/A](https://github.com/dbt-labs/dbt-core/issues/N/A))
- Add the `builtin_macros_prefer_overrides` behavior flag (default false). When enabled and the macro search package is itself internal (e.g. dbt or dbt_postgres, as for builtin macros run via `adapter.execute_macro`), the adapter override is preferred over the base dbt implementation and a root-project macro always wins. It is off by default because a root-project macro that shares a builtin's name can otherwise hijack calls made inside dbt's own macros. ([#16540](https://github.com/dbt-labs/dbt-core/issues/16540))
- Stop overriding `model`, `sql` and `compiled_code` in the microbatch batch context, so contract `data_type` aliases (e.g. `string`, `float`) are translated and contracted microbatch models no longer fail with an untranslated type ([#16757](https://github.com/dbt-labs/dbt-core/issues/16757))
- Accept the dbt v2-only `info_schema`, `check-paths` and `checks` keys in dbt_project.yml, ignoring them with a note that they are specific to the dbt v2 engine ([#16640](https://github.com/dbt-labs/dbt-core/issues/16640))
- Ignore manifest nodes with resource types dbt-core doesn't support, such as dbt v2 checks, when loading a manifest for --state and --defer ([#16849](https://github.com/dbt-labs/dbt-core/issues/16849))
- Supply credentials for `dbt deps` git packages through a git credential helper instead of embedding them in the clone URL, so clones of redirecting repositories keep working with libcurl 7.81.0-1ubuntu1.30 and later ([#16861](https://github.com/dbt-labs/dbt-core/issues/16861))
- Fix `dbt deps` failing with "could not read Username" when installing a git package from a `subdirectory` with credentials in the URL, by supplying credentials to the checkout's `git reset --hard` as well ([#16861](https://github.com/dbt-labs/dbt-core/issues/16861))
- Fix slow builds in projects whose macros read the `graph` context variable at run time (e.g. dbt-unit-testing) by converting each node to a dictionary once when the graph is built, as in 1.11, instead of on every read ([#15997](https://github.com/dbt-labs/dbt-core/issues/15997))
